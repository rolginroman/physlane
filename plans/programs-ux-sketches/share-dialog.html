share-dialog

P0 Visibility state machine made legible · opened from editor and library · journeys B4, B5, C3, C4

One question — "Who can open this program?" — with three answers. The current state is marked "Current". Selecting another answer only reveals its action and consequence; nothing changes until the action button. Mobile: bottom sheet. Desktop: centered dialog (same markup). Author-side words (Draft / Unlisted / Public) are the CONTEXT.md terms, each with a plain-language line.

1 · Draft → share link in one tap (B4, Leo's path)

Default selection in Draft is Unlisted, so the primary button is already "Create share link". Tap 1: Share. Tap 2: Create share link. Tap 3: Copy. Slugs are minted silently from the display name at this moment — no profile setup here.

2 · Unlisted: replace link, make public, move to draft (C3, C4)

Every link-killing action is confirm-gated with one consequence sentence. Replace = rotation (author label chosen over "rotate" for plainness; see notes §5).

3 · First go-public: profile setup step, then "what changed" (B5)

Only the first time an author goes public. Two steps inside the same dialog; display name prefilled from the account first name, author slug prefilled from the slug minted at first share (or suggested from the display name). Full validation states live in profile-setup.

4 · Public: de-list (C4) — confirm-gated

Public → Draft and Public → Unlisted both remove the public address; each confirm says exactly which addresses die and that the address is kept for re-listing.

5 · Pending · error · moderation-hidden · long URL

Pending: the action button shows its loading state; radios disabled. Error: nothing changed, say so. Hidden by moderation (hiddenAt): core refuses transitions, so all options are disabled with the reason. Long slugs truncate with ellipsis; Copy always copies the full URL. Empty / anonymous / minimal: not applicable (author-only dialog; Draft is the empty state).
