P0 Author editor · /programs/$programId (author only) · journeys A7, B2, B3, C1, C2

Week tabs → session cards → entry rows. Autosave per session (whole-session payload with the program revision); the save indicator is the only "save" UI. Optional fields say "(optional)" and never block sharing. Mobile: one entry expanded at a time. Desktop: weeks move to a left rail and entries become an inline-editable table.

1 · Populated + long content — live public program (C1, C2)

12 weeks, 8-entry session with two superset chains, one entry expanded. "Copy week" sits beside the week heading — the most prominent action after content. On public programs a one-line note answers the C2 fear: edits never change addresses.

2 · Copy week (C1)

Default target = next week. Copying into a week that has sessions replaces them — the option says how many, and the button turns destructive. Target "new week" appends after the last week.

3 · Autosave and stale revision (C2)

Indicator states in the top bar. A stale revision (another tab or device saved first) pins a banner, pauses autosave, and keeps the author's unsaved session visible so nothing is silently lost. Reload is the only primary action.

4 · Program settings sheet

Everything not asked at creation. Visibility is a row that opens the share dialog — one place for state changes. Program address appears only after first share (slug is minted then); renaming it redirects old addresses.

5 · Empty · minimal · fork landing · loading · error

New program lands on week 1 with one primary action. Empty session shows its own add button. Minimal (Leo) rows show only sets × reps. Fork landing shows attribution under the title (A7). Non-author opening this URL → plain 404 (NOT_AUTHOR is never surfaced as text). Anonymous → sign-in.
